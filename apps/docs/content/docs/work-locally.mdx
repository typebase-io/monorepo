---
title: Work Locally
description: Run your Typebase server on localhost during development.
---

For most day-to-day work, the simplest setup is to deploy your server to `dev` once and point your frontend at the deployed URL. Your frontend hot-reloads instantly, and you redeploy the backend with `npx typebase-io-cli deploy dev` whenever you change it.

But sometimes you want to iterate on server code without redeploying (for debugging, working offline, or just a faster feedback loop). In those cases you can run the server on your own machine.

## Generate the server

```npm
npx typebase-io-cli generate-server
```

This writes a runnable server to `typebase/_server/`. See the [generate-server reference](/docs/cli/generate-server) for output formats and adapters.

<Callout type="warn">
  Each run is a snapshot of your `typebase/` directory. Re-run `generate-server` any time you change anything inside `typebase/`, whether that's an
  action, your schema, your auth config, your env schema, or your publisher. Or use [watch mode](#rebuild-on-every-change) to have it re-run for you.
  Re-running replaces `typebase/_server/` with a fresh build, but your `.env` and installed `node_modules` are preserved.
</Callout>

## Start it

```bash
cd typebase/_server
npm install
npx tsx src/index.ts
```

The server listens on `http://localhost:8080` by default. Pass `--port` to `generate-server` (or set `server.port` in `typebase.json`) to use a different port.

<Callout type="info">
  `generate-server` defaults to TypeScript output and the `node` adapter. If you'd rather run plain JavaScript, pass `--output esm` or `--output cjs`
  and run the built files with `node src/index.js`.
</Callout>

## Rebuild on every change

Passing `--watch` keeps `generate-server` running and rebuilds whenever a file inside `typebase/` changes:

```npm
npx typebase-io-cli generate-server --watch
```

Press `x` or Ctrl+C to stop it. The first build reports each step; later ones are a single `Regenerating...` line. A build that fails (a type error,
usually) is printed and leaves the watcher running, so fixing the file triggers the next attempt.

<Callout type="warn">
  Watch mode rebuilds the files in `typebase/_server/`, but the server process you started from them keeps running the old code. Restart it to pick up
  a rebuild, or let [`--command`](#rebuild-and-restart-in-one-command) do it for you.
</Callout>

## Rebuild and restart in one command

`--command` runs a command inside the generated server after every build, and restarts it on every rebuild. That gives you one process to start and
nothing to remember: edit a file, and what is running is the new build.

Install the generated server's dependencies once:

```npm
npx typebase-io-cli generate-server
```

```bash
cd typebase/_server
pnpm install
```

Then, from your project root:

```npm
npx typebase-io-cli generate-server --watch --command "pnpm start"
```

Press `x` or Ctrl+C to stop; the server stops with it. Regenerating keeps `node_modules` and `.env`, so the install above is a one-time step.

## Environment variables

The generated server reads its config from a `.env` file in `typebase/_server/`. At minimum you'll need:

```bash title="typebase/_server/.env"
DATABASE_URL=postgresql://...   # only if your project has a db/schema.ts
BETTER_AUTH_SECRET=...          # only if your project has an auth.ts
```

Plus every key you declared in [`typebase/env.ts`](/docs/env). The server validates all of them on startup and exits with a list of what's missing, so you don't have to guess:

```
✗ Typebase server failed to start.

  Invalid environment variables:
    RESEND_API_KEY  Required

  Set them with:
    npx typebase-io-cli env <target> add <KEY> <value>
```

Locally, add them to `typebase/_server/.env` instead and restart. The `.env` file survives re-running `generate-server`.

The easiest way to get these values is to run `npx typebase-io-cli deploy dev` or `npx typebase-io-cli deploy prod` (or the equivalent `npx typebase-io-cli db <target> push`, or `db <target> migrate` in [migrations mode](/docs/database/migrations)) once. That provisions the Neon branch, writes the connection string to your project-root `.env`, and syncs the secrets to your provider.

<Callout type="info">
  The generated server reads a plain `DATABASE_URL`, but the CLI stores both connection strings in your project-root `.env` under different keys so
  they can coexist:

- `DATABASE_URL` → prod branch
- `DATABASE_URL_DEV` → dev branch

For local development, copy whichever branch you want to run against into `typebase/_server/.env` as `DATABASE_URL`:

```bash title="typebase/_server/.env"
# running against the dev branch: paste DATABASE_URL_DEV from your project-root .env
DATABASE_URL=postgresql://...
```

Most of the time you'll want the dev branch so local experiments don't touch production data.

</Callout>

If the value isn't in your project root yet (for example, on a fresh machine), you can fetch it from the provider. Pick the target that matches the branch you want.

Dev branch:

```npm
npx typebase-io-cli env dev get DATABASE_URL
```

```npm
npx typebase-io-cli env dev get BETTER_AUTH_SECRET
```

Prod branch:

```npm
npx typebase-io-cli env prod get DATABASE_URL
```

```npm
npx typebase-io-cli env prod get BETTER_AUTH_SECRET
```

If a command prints `ENCRYPTED`, that provider is hiding the raw secret value. In that case, copy the value from the original source instead: the Neon console for `DATABASE_URL`, or the provider dashboard for `BETTER_AUTH_SECRET`.

## Point your frontend at localhost

In your frontend project's `.env`, override the server URL so your client hits localhost instead of the deployed server:

```bash title=".env"
TYPEBASE_APP_URL=http://localhost:8080

# Or

TYPEBASE_APP_URL_DEV=http://localhost:8080
```

<Callout type="info">
  The CLI stores both deployment URLs in your project-root `.env` under different keys so they
  can coexist:

- `TYPEBASE_APP_URL` → prod deployment
- `TYPEBASE_APP_URL_DEV` → dev deployment

</Callout>

## Trusted origins for auth

If you have an `auth.ts` file, add your frontend's local origin to `trustedOrigins` so the local server accepts its requests:

```ts title="typebase/auth.ts"
export const auth = defineAuth({
  trustedOrigins: ['http://localhost:3000', 'http://localhost:3001'],
  emailAndPassword: { enabled: true },
});
```

Use whatever ports your frontend and server actually run on.

## Pushing schema changes

You can apply schema changes to your dev Neon branch without doing a full deploy:

```npm
npx typebase-io-cli db dev push
```

This is the same command `npx typebase-io-cli deploy dev` runs under the hood, so your local server and your next deploy stay on the same schema.

If you'd rather run your local server against a Postgres instance on your own machine (Docker, Postgres.app, etc.) instead of a Neon branch, point `db local push` at it:

```npm
npx typebase-io-cli db local push --url postgres://localhost:5432/mydb
```

You can also set `DATABASE_URL` (in your shell or in `typebase/_server/.env`) and omit the `--url` flag. See the [db local push reference](/docs/cli/db#db-local-push) for details.
